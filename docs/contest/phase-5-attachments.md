# 第五阶段：附件问答

## 已实现范围

- 使用 HarmonyOS 系统文件选择器选择单个 `.txt`、`.md` 或 `.docx` 文件。
- 附件在设备本地读取和提取文字，不上传到项目自有服务器。
- TXT/MD 按纯文本读取；DOCX 在应用缓存目录解压并读取 `word/document.xml`。
- 单文件原始大小限制为 8 MB，DOCX 解压前检查原始内容大小不超过 20 MB。
- 送入模型的附件正文最多 16000 个字符，界面明确显示是否截断。
- 普法模式和案件模式均支持“只上传文件直接提问”，也支持“文字问题 + 附件”。
- 聊天气泡只显示用户问题和附件名；实际附件正文只放入本轮 API 请求，不回显到聊天记录。
- 附件正文被明确标记为待分析数据，不能覆盖系统指令。

## 模拟器验收

测试环境：HarmonyOS 6.1.0 (23) 手机模拟器。

### TXT

- 文件：`attachment-test.txt`
- 本地提取：94 字
- 测试事实：月薪 8000 元、没有签订书面劳动合同、拖欠两个月工资
- 结果：模型正确识别欠薪和未签合同两个问题。
- 检索依据包含《中华人民共和国劳动合同法》第十条、第八十二条、第八十五条，
  《中华人民共和国劳动合同法实施条例》第六条、第七条等候选原文。
- 未再出现早期测试中的无依据“6000 元封顶”说法。
- 输出中的 Markdown 星号、反引号和标题井号由应用在显示前清理。

### DOCX

- 文件：`attachment-test.docx`
- 本地提取：104 字
- 测试事实：月薪 10000 元、未签书面劳动合同、公司口头解除
- 结果：模型正确提取劳动者、单位、入职时间、薪资、合同和解除事实，并追问案件地点、
  单位全称、解除理由与证据。
- 本轮六条依据均来自《中华人民共和国劳动合同法》核心条文及其实施条例，
  不再混入与案件无关的仲裁衔接文件。

## 检索与安全修正

- 法条检索优先命中《劳动合同法》核心条文，并区分该法与《劳动合同法实施条例》。
- “未签”“没有签订”“未订立”“书面劳动合同”等自然语言表达使用同一组召回规则。
- 组合案件允许同一核心法律返回多条不同条文，其他文档仍限制最多两条，减少噪声。
- 默认每轮最多展示六条本地候选依据。
- 模型只能使用本轮提供的 `[K1]` 等引用编号；不存在的编号在显示前移除。
- 对时效、期限、比例、具体月数或日数等规则，系统提示要求同句引用直接支持的候选原文。

## 已知边界

- 不支持 PDF、图片和扫描件，第一版不做 OCR。
- DOCX 只提取正文文字，不保留表格样式、图片、批注和修订记录。
- 内置资料属于机械收录，未完成全面法律效力审查；界面持续提示以官方最新文本为准。
- AI 输出仍可能有误，不能替代律师意见或司法机关判断。
