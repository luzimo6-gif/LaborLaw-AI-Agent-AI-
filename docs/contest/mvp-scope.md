# HarmonyOS 参赛版冻结范围

## 产品定位

面向普通劳动者和求职者的劳动法 AI 助手。应用保留原演示版的两种模式：

- 普法模式（Quick）：文字问答、附件辅助问答、本地法条检索和引用。
- 案件模式（Case）：整理六项案件信息、逐项追问、法条检索、报告生成与复核。

## 运行架构

应用使用 ArkTS/ArkUI 原生实现，直接调用用户配置的 OpenAI 兼容模型 API。
不部署项目自有服务器，不依赖 FastAPI、Python 或 LangGraph 运行环境。

本地知识库在开发阶段由 Mac 一次性生成，随 HAP 以只读资源发布。第一版采用
关键词和加权文本检索，不使用 Python `vectorstore.pkl`、向量数据库或 GraphRAG。

## 数据范围

原始资料来自开发者本机保存的劳动法律资料目录。原始 487 MB 语料不提交到仓库，
公开仓库只保留供 App 运行的紧凑只读索引及其构建报告。

参赛版按当前决定机械收录资料目录中的全部 2790 个源文件：

- `法律/`：6 份
- `行政法规/`：11 份
- `规章及法律规范/`：67 份
- `地方法律 法规规章/`：2706 份

其中 2761 份已提取正文并可检索，29 份图片、扫描件、异常下载文件或不可读取
压缩包按既定边界只保留文件信息。仍不进行去重、失效清理、版本合并或全面法律
效力核验。引用界面必须展示原始文件名，并提示用户通过官方渠道核对最新效力状态。

## 必做功能

1. API 配置、连接测试和安全存储。
2. 普法模式多轮问答。
3. 案件模式六项卷宗、追问和报告。
4. 本地法条检索与引用 ID 校验。
5. TXT/MD、DOCX 附件读取。
6. 网络错误、超时和无配置状态处理。
7. 悬浮/沉浸导航、自适应布局、最小服务卡片。

## 明确不做

- OCR、图片和扫描 PDF。
- 登录注册、云同步和自建后台。
- 多供应商管理后台。
- 数据反馈飞轮和知识库管理页。
- 数据清洗、向量检索和 GraphRAG。
- 正式应用市场上架。

## 第一阶段验收

1. DevEco Studio、HarmonyOS SDK 和模拟器可用。
2. 原生工程创建在 `harmony-app/`。
3. 空 HAP 能从命令行或 DevEco Studio 清洁构建。
4. HAP 能在模拟器启动。
5. 构建命令、SDK/API 版本和已知阻塞记录在项目文档中。
